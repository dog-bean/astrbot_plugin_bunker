# 防空洞（astrbot_plugin_bunker）

在 AstrBot WebUI 的插件扩展页里，开一条**不依赖 QQ 登录**的旁路聊天通道：还是同一个 Bot 人格、同一份会话记忆，只是入口从 QQ 换成了浏览器。

## 为什么需要它

QQ 适配器掉线、风控、账号出问题时，Bot 本身还在跑，但你已经没法跟它说话了。防空洞把网页里的输入装成一条真实的私聊事件，走 AstrBot 自己的处理流水线，所以对模型来说这就是「主人发来的消息」，记忆和人格都不串。

## 原理

1. 用配置里的 `platform_id` + `owner_qq` 构造一个 `aiocqhttp` 平台的私聊事件（`AstrMessageEvent`）。
2. 事件交给 AstrBot 正常处理，回复被截获后写进插件自己的历史文件。
3. 网页通过插件拓展页 API 拉取历史，并把新消息提交进来。

不经过 QQ 服务器，也不经过任何第三方协议。

## 安装

把整个目录放进：

```
AstrBot/data/plugins/astrbot_plugin_bunker
```

然后在 AstrBot 里重载插件（或重启）。

要求：**AstrBot >= 4.22.0**（需要插件拓展页 Web API 支持）。

## 配置

| 配置项 | 必填 | 说明 |
| --- | --- | --- |
| `owner_qq` | 是 | 旁路通道伪装成这个人的私聊。填你自己的 QQ 号，必须和 QQ 适配器里那个账号一致。 |
| `platform_id` | 是 | 复用的平台标识，必须和 QQ 适配器的平台 ID 一致，否则会变成另一个空白会话。 |
| `sender_name` | 否 | 事件里记录的昵称，只影响显示。 |
| `bot_name` | 否 | 网页左侧回复的显示名。 |
| `reply_timeout` | 否 | 网页等待回复的秒数，默认 180。超时只是网页提示，模型仍可能把回复发到 QQ 那边。 |
| `max_history` | 否 | 网页保留的历史条数，默认 300。只影响网页显示，不影响模型上下文。 |

> `platform_id` 和 `owner_qq` 填错是最常见的「防空洞里 Bot 失忆」原因，对照 QQ 适配器配置抄一遍。

## 使用

- **网页**：WebUI → 插件 → 防空洞，直接输入。
- **QQ 端自测**：发送 `/防空洞自测`，会往防空洞里丢一条测试消息，验证通道是否走通。
- **LLM 工具**：`bunker_leave_message`，让 Bot 主动往防空洞留一句话。

## 安全提示

- 这是本机自用通道，**不要把 WebUI 端口暴露到公网**。防空洞的访问控制继承 WebUI 的登录状态。
- `/防空洞自测` 和 `bunker_leave_message` 只对 `owner_qq` 生效，其他人调用会被拒绝。

## 已知限制

- 只支持 `aiocqhttp` 平台事件构造。
- 网页历史存在插件自己的数据目录（`history.json`），和 AstrBot 主数据库分离。
- 依赖 AstrBot 的插件拓展页 Web API，版本过低会注册失败（日志里会有 `[Bunker] 当前 AstrBot 不支持插件拓展页 API`）。
